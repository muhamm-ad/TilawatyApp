# Tilawaty Issues

**Public issue tracker for [Tilawaty](https://tilawaty-iota.vercel.app)** — a Quran reader with reading-progress tracking for Muslims who read regularly or complete a khatma (full reading). Available on Android and iOS, with a web build. The UI is in English and French. All data stays on your device; there is no account and no analytics.

> The app source code lives in a **private** repository. This repository exists so anyone can report bugs, request features, and discuss ideas without needing access to the source. This follows [GitHub’s issues-only repository pattern](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-an-issues-only-repository).

## How to report a bug

1. Open a [new bug report](https://github.com/muhamm-ad/Tilawaty-Issues/issues/new?template=bug_report.yml).
2. Fill in the form (app version, platform, steps to reproduce, expected vs actual, screenshots if useful).
3. Submit. Maintainers will triage and may ask for more detail.

**Do not** attach personal notes or a full backup file unless you choose to and have removed private notes first. Never include passwords or other personal data.

## How to request a feature

1. Open a [feature request](https://github.com/muhamm-ad/Tilawaty-Issues/issues/new?template=feature_request.yml).
2. Describe the problem you want solved and your proposed idea.
3. Feature ideas need **maintainer confirmation** before they go on the backlog. Filing a request does not guarantee it will be built.

## Quran text or translation errors

Use the [translation / content report](https://github.com/muhamm-ad/Tilawaty-Issues/issues/new?template=translation_or_content.yml) for mistakes in Quran text display or in the English (Pickthall) / French (Hamidullah) translations.

## Questions and ideas

For general questions or open-ended discussion, use [Discussions](https://github.com/muhamm-ad/Tilawaty-Issues/discussions) instead of issues.

## Security

If you believe you found a security vulnerability, **do not** open a public issue. Report it privately via [GitHub Security Advisories](https://github.com/muhamm-ad/Tilawaty-Issues/security/advisories/new). See [SECURITY.md](SECURITY.md).

## What happens after you file an issue

1. **Needs triage** — new issues get the `needs-triage` label.
2. **Triage** — the maintainer reviews, may ask for info (`needs-info`), confirm the bug, or decline duplicates / out-of-scope items.
3. **Backlog** — confirmed work is prioritized (`priority: high|medium|low`) and labeled by area.
4. **Tracked** — some issues may get `tracked-in-app` when mirrored in the private app repo for development.
5. **Resolution** — only the maintainer closes issues. Descriptions filed by reporters are not edited; updates go in short comments.

## Labels (quick guide)

| Kind | Examples |
|------|----------|
| Type | `bug`, `enhancement`, `documentation`, `question` |
| Status | `needs-triage`, `needs-info`, `confirmed`, `tracked-in-app`, `duplicate`, `invalid`, `wontfix` |
| Priority | `priority: high`, `priority: medium`, `priority: low` |
| Area | `area: reading`, `area: progress`, `area: audio`, `area: translations`, … |
